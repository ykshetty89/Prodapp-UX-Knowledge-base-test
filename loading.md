### Hub Worker Loading — Two Scan Flows (Flow A vs Flow B)
- **Date:** 01 Jun 2026
- **Author:** Prodapp UX team
- **Source:** PDF — Hub Worker Loading UX Research Synthesis
- **Tags:** #loading #scan-flow #flow-a #flow-b #hubworker #route-card

Two distinct loading flows exist. Flow A: HW scans all items and the system matches them to the pre-planned route — used in Driver Glow today, non-scannable items added via confirmation screen. Flow B: HW selects a route card in Hubworker first, then scans items for that specific route — currently live in Hubworker, more deliberate but slower to start.

### Loading Stage — Scan Items Cognitive Load and Errors
- **Date:** 01 Jun 2026
- **Author:** Prodapp UX team
- **Source:** PDF — Hub Worker Loading UX Research Synthesis
- **Tags:** #loading #scanning #zebra #route-mismatch #cognitive-load

Workers scan each parcel with a Zebra device and the system verifies against the pre-planned route. Cognitive load is medium but exceptions cause hesitation — workers trust the scan but errors are high-stakes. When a scanned item does not match the planned route (e.g. it should go to a DIP), the system does not clearly communicate this, forcing a real-time judgment call on a noisy terminal floor.

### Loading Confirmation — Redundant Step After Scanning
- **Date:** 01 Jun 2026
- **Author:** Prodapp UX team
- **Source:** PDF — Hub Worker Loading UX Research Synthesis
- **Tags:** #loading #confirmation #redundant #scanning #friction

Workers must confirm loading complete even when every item has already been counted by scanning. This redundant step undermines worker trust in the scan as source of truth and creates a procedural friction point with no perceived value. Particularly damaging in a time-pressured physical environment where every extra tap has a real cost at scale.

### Truck Physical Constraints — Compartments and Placement Order
- **Date:** 01 Jun 2026
- **Author:** Prodapp UX team
- **Source:** PDF — Hub Worker Loading UX Research Synthesis
- **Tags:** #loading #truck #placement-order #compartments #roller-cage

Trucks are divided into 16 compartments with a max of 18–20 roller cages or pallets (5–7 stops maximum). Placement order matters for driver route efficiency but the app does not currently communicate this. Wrong load order forces re-sequencing mid-route for the driver. No visual loading map exists showing where in the truck items should go.

### Design Opportunity — Loading Overview Before Scanning Begins
- **Date:** 01 Jun 2026
- **Author:** Prodapp UX team
- **Source:** PDF — Hub Worker Loading UX Research Synthesis
- **Tags:** #loading #design-opportunity #overview #mvp #scanning

High priority MVP opportunity: give HWs a clear loading overview (what goes on this truck, in what order) before scanning begins. Currently no consolidated pre-scan view exists — workers must mentally construct the load plan from dispatcher briefings, physical maps, and the Hubworker app, which can conflict with each other.
